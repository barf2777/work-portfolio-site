Case study

AD hygiene and LAPS

Active DirectoryLAPSstale computer objectsprivilege tracing

Scale single forest, 2 domain controllers · ~40 Group Policy Objects inherited across tiers · inherited non-English install locale complicating built-in group names

Situation

Directory drift: stale computer accounts, unclear local-admin paths, need for randomized local admin passwords.

Task

Clean inactive computers, introduce LAPS thinking, and make “who has admin?” answerable.

Approach

  1. Scripted/process cleanup of inactive computer objects with change control.
  2. Deploy or stage Windows LAPS with clear recovery story for helpdesk.
  3. Trace nested group rights instead of guessing from local Administrators screenshots.
  4. Prefer AD-group local admin over random local accounts.

Result

  • Smaller attack surface from stale objects; clearer privilege model.
  • Helpdesk-ready local admin recovery pattern.

Interview soundbites

“Stale computer objects are inventory debt with security interest.”
“If you can’t explain who has admin, you don’t have least privilege.”
