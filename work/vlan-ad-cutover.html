Case study

VLAN and Active Directory cutover

Active DirectoryDNSDFSMikroTik firewallWireGuardphased cutover

Scale multi-building campus · ~25 routed VLANs · 2 domain controllers · ~30 virtual guests affected

Situation

Brownfield manufacturing campus. Domain controllers, file servers, and mixed workloads shared a legacy server VLAN with cameras and other noise. Remote access still included WAN DST-NAT and port-knock patterns that no longer matched the threat model.

Task

Move identity and core file services onto a dedicated server VLAN, keep production online, and retire internet-facing RDP/SSH holes in favor of VPN-only admin access.

Approach

  1. Prep-not-cutover — document dual addressing, firewall address-lists, VPN peer allowed-address entries, and AD Sites before flipping IPs.
  2. Cutover in waves — storage appliances first, then application servers, then the DC pair; refresh DNS forwarders and _msdcs NS records to match reality.
  3. Expect brownfield landmines — stale static DNS on file servers breaks domain secure channel and DFS management even when DCs are healthy; vendor apps that hardcode share IPs fail until the vendor updates the path.
  4. Harden the edge in the same program — remove WAN DST-NAT for RDP/SSH and narrow noisy UDP input to the VPN interface list after verifying camera/VPN paths.
  5. Verify interface membership — a new VLAN that is not on the router’s LAN interface list breaks DC→router DNS resolution in subtle ways (NXDOMAIN for internal names).

Result

  • DCs and primary file/app servers live on the dedicated VLAN; DHCP DNS/NTP for campus clients points only at the live DC pair.
  • Remote admin path is WireGuard-only; WAN RDP/SSH NAT and port-knock leftovers removed.
  • Runbook captures complications (hosts file, hypervisor tag vs IP, DFSR “namespace Offline ≠ stop replication”) so the next cutover is faster.

Interview soundbites

“I treat VLAN moves as dependency graphs, not IP renames.”
“Secure channel and DFS failures after a DC move are usually client DNS, not AD itself.”
