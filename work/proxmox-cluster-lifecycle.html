Case study

Proxmox cluster lifecycle

Proxmox VEquorumPBSupgradesrestore drills

Scale 4-node production cluster (~700 GB RAM, ~15 TB ZFS) plus a separate lab cluster · ~30 VMs and containers · Backup Server with scheduled datacenter jobs

Situation

On-prem workloads needed a real cluster (not a single tower), backups that could restore, and a path to major VE upgrades.

Task

Build and operate a multi-node Proxmox environment: quorum, backup to PBS, guest storage pitfalls, upgrade prep.

Approach

  1. Add nodes carefully; use QDevice when even counts threaten quorum.
  2. Separate hypervisor backup (PBS) from file-level backup products.
  3. Practice restore — prune policy means nothing without a restore drill.
  4. Diagnose Windows-on-ZFS latency as storage+guest, not “Proxmox is slow.”
  5. Prep VE 9 upgrades with a checklist, not Friday-night hope.

Result

  • Cluster capable of hosting identity/file/monitoring guests.
  • Operator habit: backup green ≠ restore proven.
