Network as code (MikroTik fleet)

RouterOSGitinventoryCAPsMANAnsible inventory coupling

Scale ~50 RouterOS devices (routers, switches, access points) · ~25 routed VLANs · single Ansible inventory shared with monitoring

Situation

Dozens of MikroTik devices across a campus: core routers, site edges, Wi‑Fi APs. Config lived in tribal knowledge and one-off WinBox sessions. Identity↔IP mismatches made monitoring and backups unreliable.

Task

Make router configuration reviewable and recoverable: Git-tracked exports, a single inventory of mgmt IPs, and a clear split between controller Wi‑Fi changes and edge local changes.

Approach

  1. Nightly (or on-demand) text exports into Git — human-diffable .rsc, not only binary backups.
  2. Reconcile inventory vs live DHCP — fix wrong identity↔IP rows; treat “waiting” leases as offline, not mystery hosts.
  3. CAPsMAN literacy — real Wi‑Fi edits live on the controller; CAP files that only show managed-wlan drift are sync echo, not fifteen separate changes.
  4. Cross-repo coupling — backup inventory and monitoring inventory share mgmt IPs; adding a router means explicit IP args, not auto-discover magic.
  5. Commit message discipline — name the intentional device/controller change; never paste PSKs or communities into Git messages.

Result

  • Operators can answer “what changed on the core last week?” from Git history.
  • Monitoring and backup targets stay aligned with the same mgmt addressing model.
  • Wi‑Fi reviews focus on the controller, not noise on every AP export.
